Algunos nodos de workflow invocan servicios protegidos: APIs externas, plataformas de rastreo o el propio Fail Fast. Una credencial guarda la autenticación que esas llamadas necesitan. Creas una credencial una vez y todos los workflows de tu espacio de trabajo pueden reutilizarla: la actualizas en un solo lugar y todos los nodos que la usan reciben el cambio.

<Note>
Las credenciales se gestionan desde los propios nodos del workflow. Cuando configuras un nodo que requiere autenticación, eliges una credencial existente o creas una nueva ahí mismo; no hay una pantalla de credenciales aparte que debas visitar primero.
</Note>

## Tipos de credencial genéricos

Para los nodos que invocan servicios arbitrarios — el caso más común es el nodo **Solicitud HTTP** — eliges el método de autenticación que espera el servicio destino:

| Tipo | Qué cubre |
|---|---|
| Basic Auth | Usuario y contraseña enviados en cada solicitud. |
| Bearer Auth | Un token bearer enviado en cada solicitud. |
| Custom Auth | Un esquema de autenticación personalizado definido por ti. |
| Digest Auth | Autenticación por desafío basada en digest. |
| Header Auth | Un valor de autenticación enviado en un encabezado de la solicitud. |
| OAuth2 API | Se conecta mediante un flujo de autorización con el servicio. |
| Query Auth | Un valor de autenticación enviado como parámetro de consulta. |
| JWT Auth | Autenticación con un JSON Web Token. |
| None | Sin autenticación, para servicios abiertos. |

## Credenciales de servicios predefinidos

Los nodos de servicios específicos vienen con su propio tipo de credencial, ajustado a lo que ese servicio requiere. Existen credenciales predefinidas para los nodos **Fail Fast**, **Truora**, **Monitor**, **RNDC** y **Satrack**. Cuando configuras uno de estos nodos, te pide la credencial correspondiente — consulta la [Referencia de nodos](/es/automation/nodes) para saber qué hace cada uno.

## Crear una credencial desde un nodo

<Steps>
  <Step title="Abre la configuración del nodo">
    En el lienzo del workflow, abre el nodo que necesita autenticación.
  </Step>
  <Step title="Elige o crea una credencial">
    En el selector de credenciales, elige una credencial existente, o crea una nueva si ninguna sirve.
  </Step>
  <Step title="Completa los datos de autenticación">
    Ingresa lo que pide el tipo de credencial: un token, un usuario y contraseña, o el valor de un encabezado.
  </Step>
  <Step title="Guarda y continúa">
    Guarda la credencial. El nodo ya la usa y queda disponible para reutilizarla en otros workflows.
  </Step>
</Steps>

## Conectar una credencial OAuth2

Las credenciales OAuth2 no reciben un secreto fijo: se conectan mediante un flujo de autorización con el propio servicio.

<Steps>
  <Step title="Crea una credencial OAuth2 API">
    Desde el selector de credenciales del nodo, crea una credencial nueva y elige el tipo OAuth2 API.
  </Step>
  <Step title="Completa el flujo de autorización">
    Sigue el flujo de conexión para autorizar a Fail Fast ante el servicio externo, iniciando sesión y otorgando acceso del lado de ese servicio.
  </Step>
  <Step title="Úsala en tus nodos">
    Una vez conectada, selecciona la credencial en cualquier nodo que invoque ese servicio.
  </Step>
</Steps>

<Tip>
Reutiliza una sola credencial por servicio en todos tus workflows en lugar de crear duplicados. Cuando cambie el token o la contraseña del servicio, actualizas una única credencial y todos los workflows siguen funcionando.
</Tip>

## Credenciales frente a claves API

Las credenciales autentican tus workflows ante servicios externos. Si lo que necesitas es que un sistema externo se autentique ante Fail Fast, eso se maneja con [claves API](/es/admin/api-keys).
